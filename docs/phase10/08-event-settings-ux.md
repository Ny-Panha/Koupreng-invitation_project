# Event Settings

Settings keeps one existing form/save queue and the canonical InvitationRequest endpoint. General, Privacy & access, RSVP & guests and Team anchors organize actual supported settings. Grouped cards, comfortable fields, native focus/validation and a sticky safe-area-aware save bar work across mobile/desktop. Team links to the real module; there are no fake notification or danger-zone controls.

Visibility changes require confirmation at save, retain the current password when blank and remain owner-only. RSVP deadline uses the existing LocalDate DTO and cannot exceed the event date through native validation. Opening the page sends no writes. Recoverable errors preserve values; 409/401 retain existing actionable conflict/session handling and private draft download.

Real local browser/API/MySQL evidence verifies read/edit/save/reload, shared Studio title, RSVP deadline and a concurrent authoritative update followed by an actual 409. Fixture cases verify declining/accepting visibility confirmation, responsive captures and scoped axe. Existing backend ownership, access/password, collaboration and OpenAPI tests remain the authority for permissions.

A subsequent Studio save now explicitly retains the Settings-owned canonical RSVP deadline. Both a dated value and an explicit null have component regression cases; the native journey and direct SQL verify the dated value survives Studio edits and publication.

No schema or API extension was necessary. Unsupported notifications and destructive operations were not invented. Manual screen-reader and device review remain outstanding.
