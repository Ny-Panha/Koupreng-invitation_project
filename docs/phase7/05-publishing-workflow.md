# Publishing and generic invitations

Both decorated wedding Studio and Event Essential/generic events now expose the same five creation steps. Advanced editing remains available. The generic editor reuses the existing Studio persistence guard for serialized writes, expected server revision, retained 401/409 edits, explicit retry, leave warning and private JSON recovery. Its preview/guest/RSVP actions save successfully before navigating. Optional contact, message and schedule content remain optional. Draft saves can remain incomplete; publication uses the readiness checklist and backend validation.

The event overview's unpublished action links to guided review rather than directly calling publish. Publication requires a review dialog and explicit confirmation. The editor first flushes saves, calls the existing owner-only endpoint, and shows the public URL only after a PUBLISHED response with a server slug. The returned updatedAt becomes the next edit's expected revision. Failed/uncertain publication preserves the draft and offers a server status check. Private and password-protected rules remain enforced by the existing backend; publication does not bypass visibility. The backend also validates RSVP deadline ordering and any required password; the UI checklist is guidance and does not replace these rules.

The generic editor uses the existing saved-preview route after a confirmed save. It does not provide the decorated wedding editor's simultaneous live split preview; this is an explicit renderer difference, not simulated preview support.

Verification: `m6-final-user.log` has 17 passing tests (generic save/publish ordering, server URL, post-publish revision, conflict retention and Studio regressions). User lint/build passed. `m6-publish-browser.log` has 19 passing Chromium cases: the three existing decorated renderers' address persistence/publication, blank-address validation, save/publication failure, generic guided publication, KH/EN generic captures at nine widths, and decorated Studio save/preview/focus/conflict regression at nine widths. These browser cases use fictional intercepted contracts; actual HTTP authorization and save concurrency are covered separately by the disposable-MySQL suite.
