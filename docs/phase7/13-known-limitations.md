# Known limitations and external validation

- **Release scope:** Ready for code review after the local gates, not a production release approval. Staging migration/backup/rollback rehearsal, environment-specific authorization and external integrations still require validation.
- **External providers:** No live ABA payment, bank alert, Telegram delivery, email delivery, Google/Telegram OAuth or Cloudinary transaction was performed. The private test runtime has no live provider credentials. Team invitations use explicit privately shared codes; the UI states that no email was sent.
- **Physical accessibility:** Playwright Chromium/Firefox/WebKit and viewport/text-size checks are automated desktop-engine coverage. Physical Android/iPhone, software keyboards, iOS safe-area/browser chrome, manual screen-reader operation and Khmer editorial review remain unverified. No WCAG or physical Safari certification is asserted.
- **Collaboration:** Effective roles apply to all events the owner links to the organization. Capacity counts membership entries, including owner entries across workspaces. There are no real-time cursors/presence. A legacy ACTIVE member needs a new accepted invitation for event tools.
- **Analytics:** Daily responses represent each linked RSVP's latest stored response date; edits move the bucket. Undo/delete changes current facts. Guest record, reserved seat, confirmed attendee and active check-in units remain distinct. No DAU, MRR/ARR, churn, conversion history, verified email delivery or inferred engagement is fabricated. Historical admin chart comparisons unsupported by the existing API are explicitly unavailable.
- **Generic preview:** Generic/event-essential invitations save then open the existing preview route. Decorated wedding Studio has the live split/full-screen renderer. They are not claimed to provide identical preview modes.
- **Bulk scope:** The new bulk operation is bounded selected-record CSV export. No destructive bulk deletion, mass payment action or arbitrary status mutation was introduced. Existing authorized per-record/import workflows remain available.
- **Printing:** Existing HTML print previews remain available. Browser print-to-PDF is not a new server-generated PDF capability; a direct PDF renderer was not introduced or certified.
- **Compatibility tests:** Three Phase6DemoMySqlTests remain deliberately disabled because their provisioning guard targets the separate historical Phase 6 demo database. Equivalent Phase 7 signup/save/permission/lifecycle paths and the original browser program/story cases were exercised in the Phase 7 database. Docker was unavailable; native MySQL was used.
- **Performance limits:** Local single-concurrency benchmark results are measurements, not a production latency SLA. The existing Redis-backed distributed cache/rate-limit deployment path was not operated here. Native fallback and relevant unit tests passed.
- **Expected test diagnostics:** User happy-dom tests emit iframe-loading-disabled diagnostics; actual iframe behavior was checked in real browser engines. Worker tests emit two upstream deprecation warnings. These are retained in logs rather than presented as production failures.

The normal local checkout, development database, existing Phase 6 demo accounts and Phase 6 archive were preserved. No merge, push, deployment, production container restart, live migration or DNS change was performed.
