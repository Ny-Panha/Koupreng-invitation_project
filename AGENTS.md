# Repository agent guidance

Begin at the repository root and follow [.agents/ROUTER.md](.agents/ROUTER.md).
Select one primary skill and at most two supporting skills for the active phase;
use [.agents/SKILLS_INDEX.md](.agents/SKILLS_INDEX.md) to find their current paths.

Inspect current source and manifests before editing. Preserve unrelated work,
existing authorization and entitlement boundaries, and applied Flyway migrations.
Use focused edits and risk-based tests. Report the commands actually run and
their results, including failures and environmental limits.

See [CODEX.md](CODEX.md) for the companion workflow and command examples.

## Retained UX/UI master scope (2026-11-11)

The user asked to read and retain the complete
[27-phase UX/UI master scope](docs/uxui/MASTER_SCOPE.md), version 1.0, and will
send individual phase prompts later. The document is planning reference material;
reading or retaining it does not authorize implementation, commits, pushes, or
deployment. Follow the user's subsequent prompt for the active phase.

Read the relevant phase, dependencies, and global acceptance requirements before
phase work. The five waves cover foundations (01–06), marketplace and creator
experience (07–15), guest experience and event operations (16–21), business/admin
and CMS (22–25), and system-wide validation/release (26–27). These phase numbers
belong to this master scope; older phase folders and roadmaps may use different
numbering and do not prove completion of this program.

Preserve Khmer/English support, individual template identities, existing team
work, draft/unknown JSON roundtrips, preview protocols, authorization,
server-owned prices/entitlements, USD/KHR separation, and applied migrations.
Every authorized phase requires route/state coverage, before/after evidence,
appropriate functional/accessibility/performance checks, truthful test results,
and a documented handoff. Verified existing work may be retained. Historical
audit counts and results require current-source revalidation. Optional new
capabilities (including owner calendar, general CMS, live AI, venue booking, and
refunds) require their own explicit scope and approval.
