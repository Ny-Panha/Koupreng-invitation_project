# Calendar and program contract

`eventDate` is the main celebration's Gregorian date-only value. `eventTime` is a saved wall time, including intentional midnight, in `eventTimezone` (default `Asia/Phnom_Penh`). Existing `wallTimeToInstant` rejects DST gaps and resolves repeated wall times to the earlier occurrence. Countdown uses the existing `WeddingCountdown` / `useCountdown`; it never invents an event time for all-day weddings. Date-only arithmetic uses `calendarMonth`, `shiftMonth`, `programDate` and `groupProgram`, never device-local parsing.

`programDays` holds stable day IDs and optional dates/headings/enabled state. `schedule` holds stable ceremony IDs, `dayId`, times, localized title/description/location, icon and enabled state. Arrays define display order. `serializeProgramDays` retains unknown properties; the backend's 30-day / 200-row limits remain unchanged. Blank day dates follow the main event by day position; custom dates stay independent.

`visibleProgramDays` is the common public projection for calendar, timeline and ceremony export. It excludes disabled days/rows and hidden schedules without changing editable records. The Royal calendar derives main/secondary markers from this projection. Different symbols, borders, explicit labels and pressed state distinguish dates beyond color. A selected date can contain several program days. Its links focus the corresponding stable day anchor within the existing scroll root. Month browsing and selection reset when canonical dates change in Studio. All dates retain ISO machine values regardless of numeral selection.

Export A retains `buildEventCalendar` (one VEVENT; all-day allowed; exclusive next-day end). Export B uses `buildProgramCalendar`: one timed VEVENT per enabled, valid ceremony; no guessed legacy/free-text time or all-day ceremony. Explicit end times must follow starts on the same day. Missing ends use the existing two-hour fallback. Invalid rows are excluded and reported to the guest; an entirely invalid program produces no misleading file. UIDs combine saved `calendarUid` with stable day/ceremony IDs. Legacy records without that namespace use a deterministic fallback and acquire a persisted UUID on Studio save.

Exports use UTC instants from existing IANA conversion, CRLF, UTF-8 byte-aware line folding and escaped/bounded public text. They never serialize entire invitations, guest tokens, private messages, KHQR details or protected media references. An independent test reader unfolds content lines and verifies individual event records, temporal values and injection resistance.
