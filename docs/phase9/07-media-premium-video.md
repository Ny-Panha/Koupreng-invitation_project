# Optional Premium cinematic stage

The additive `contentJson.preWeddingVideo` object accepts only `enabled`, `videoMediaId` and `posterMediaId`. IDs must reference owned media in the same event. The video must have purpose `PRE_WEDDING_VIDEO`; its optional poster must be a validated cover/gallery image. Ordinary cover video, gallery, photos and music retain their existing contracts and access policy.

`PRE_WEDDING_VIDEO` is derived on the server from the active purchased Premium snapshot's `PREMIUM` code. A generic paid subscription, Premium-template purchase, administrator role or browser flag does not confer this capability. Snapshot contents and existing purchases are not rewritten. The existing active-benefit/expiry policy resolves the product rule: expiration suppresses public cinematic authorization and denies new media/configuration changes; saved content remains available for reactivation. Owners can disable or clear a retained configuration without renewing.

Upload, replacement, association changes, saving and publication enforce the owner's current entitlement and event permission. Public playback checks published invitation access, moderation, current Premium and the selected event-scoped ID again. The additive public `cinematicOpening` field is server-resolved; raw content JSON alone cannot authorize bytes. Public media lists omit private films and ticket-purpose assets.

Local films live outside the static upload root, in a separate configurable private directory. The backend image owns that directory; Compose persists it in `uploads-private`. Public URLs are never stored for these films. Cloudinary uses its authenticated video upload/destroy contract and a short-lived, signed server-side download request. The browser receives bytes through the checked backend endpoint, never the signed provider URL. These Cloudinary rules follow the [official access-control documentation](https://cloudinary.com/documentation/control_access_to_media) and [Upload API reference](https://cloudinary.com/documentation/image_upload_api_reference); mocked HTTP contract checks are distinct from live provider verification.

TemplateExperience wraps the established renderer registry with one shared stage that adapts the existing CinematicVideoOpening player. Existing envelope, curtain, floral, folio and other covers keep their choreography. Templates without a cover receive an optional opening entry only when the authorized film is enabled. Dedicated renderers defer their opening music until the film finishes or is dismissed; browser-denied playback leaves an explicit music retry available.

Video bytes are requested only after the guest's opening action. Muted inline playback, sound controls, immediate Skip/Escape, modal focus management, ended/error transitions, aborted fetch cleanup and a 15-second no-progress recovery prevent trapping the guest. Reduced motion bypasses the film without downloading it. The established 50 MB limit and MP4/WebM MIME/extension/signature validation remain. No transcoding service was added. Playback uses a revocable browser Blob after download, so large films can require significant memory/latency; slow transfers recover to the invitation.

Real HTTP/MySQL/local-file tests cover Free/Pro denial, forged settings, cross-event IDs, expiry, protected access, redacted listing, deletion guards and byte delivery. Local-file tests cover private-directory separation, persistence across adapter instances and ordinary-video preservation. Cloudinary upload/download-signature/deletion tests use mocked transport and fictional signing material; no live Cloudinary capability is claimed.
