# 04 — canonical tokens and implementation

The authoritative token source is `apps/frontend-user/src/shared/styles/semantic-tokens.css`; `node scripts/sync-design-tokens.cjs` regenerates the admin mirror. Legacy aliases `--ui-duration-feedback` (160ms), `--ui-duration-overlay` (200ms), and `--ui-ease-standard` remain. New tokens: `--ui-duration-press` 120ms, `--ui-duration-reveal` 240ms, `--ui-duration-ceremony` 700ms, `--ui-ease-enter`, `--ui-ease-exit`, `--ui-motion-distance` 8px, and `--ui-motion-scale` .985. The reduced-motion media block makes durations 0ms and transforms neutral. The 700ms token is a design reference, not a forced rewrite of authored scenes.

Both apps can consume CSS variables without another React runtime. User `LoadingButton` and toast entrance use shared durations. The host drawer uses transform and its existing closed-state `inert`/`aria-hidden` policy. Admin `ActionButton` uses tokenized color/opacity transitions while its size remains fixed. CSS handles ordinary states; JavaScript subscribes to motion preference only when runtime state or timers must change. The guest experience uses the existing `usePrefersReducedMotion` listener; admin `AnimatedNumber` uses `useSyncExternalStore`. Neither hook is a status authority.

Run `node scripts/sync-design-tokens.cjs --check` after any token edit. The generated admin file must not be edited manually. Renderer artwork remains outside management selectors. The broad existing admin reduced-motion override remains in place pending Phase 06 cascade review; the new tokens also provide explicit per-component zero-duration behavior.
