# 15 — account event races and revoked access

Audit date: 19 November 2026, Asia/Bangkok. Scope: local engineering and named fixtures.

A layout-effect probe records the first committed frame after account A→B. The old list and open delete target must already be absent in B; waiting for a passive reset effect is insufficient. Separate deferred tests prove A's late list reply cannot replace B, and a late synchronization cannot update B's display or claim the old record. The original draft bytes and request identity remain retained.

Workspace identity already remounts on account/event key; that is preserved. A newly reproduced access race used two independent revision domains: an initial owner response could overwrite a newer revocation. Both now share a single revision counter. An event with no current grants renders a safe denial and removes its identity/navigation; an already open Studio retains its established read-only draft recovery contract. Older refresh replies cannot restore revoked actions.
