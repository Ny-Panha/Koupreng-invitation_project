# Final route and functional coverage

Executed route factories and unit reconciliation enumerate **111 customer + 24 admin = 135 patterns**. [The machine matrix](route-matrix.json) records a concrete fixture URL, destination, access requirement, leaf contract and observed status for every row. Registration and historical modernization status are separate from runtime evidence.

The dedicated Chromium suite passes all 135 leaves using bounded, source-shaped GET fixtures. Unknown API reads return 501; mutations return 405. Unexpected reads, writes and application page errors fail. Aliases inherit actual destination content checks. A generic admin/event shell is never accepted as a leaf pass. Local drafts, numeric events, missing routes and legacy redirects have distinct contracts.

Protected content coverage is **106/106 patterns: 84 authenticated customer and 22 admin**. The other 29 are public/fallback patterns. The retained Batch 11 anonymous guard suite separately exercises all 106 protected patterns. Fixture identities do not prove backend authorization; owned-MySQL/JWT tests provide independent real API evidence.

Functional coverage is selective: template save/reload/preservation, failed and malformed load recovery, discard confirmation, immutable identity, package keyboard/focus behavior, notification server-status truth, server-controlled payment returns, denied receipts, public opening and the persistent publish/RSVP/check-in/admin-report journey. The final core/security subset runs in three engines; the complete inventory runs in Chromium.

All declared leaves now have meaningful read/render coverage. This does not establish exhaustive CRUD, every account/event/template state, all provider branches, every template variant, complete accessibility or production-scale data. [External and device limits](EXTERNAL_DEPENDENCIES.md) remain explicit. Historical route rows are not relabeled as blanket product certification.
