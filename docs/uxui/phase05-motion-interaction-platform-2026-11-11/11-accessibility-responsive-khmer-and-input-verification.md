# 11 — accessibility, responsive, Khmer/English, and input

**Source and unit checks:** The owner drawer has `inert` and `aria-hidden` while closed, gains focus inside when opened, traps Tab, and restores trigger focus on Escape or explicit dismissal. The compositor transition keeps the closed drawer offscreen; `inert` removes its controls from keyboard navigation. The shared guest gate has a Skip button with 44px minimum target and visible focus outline. Its label follows the invitation locale first (English/Khmer) and site locale for bilingual mode; a mismatched site/invitation unit case passes. Opening moves focus to Skip; completion focuses invitation content. Runtime reduced-motion change finishes an in-progress shared gate. Admin numeric motion snaps to the current value if preference changes. Existing Modal focus isolation and admin persistent error toast remain unchanged.

**Fixture checks:** The Phase 05 browser spec covers owner mobile drawer, short-landscape Studio, shared guest Skip, auth route entry, venue content, admin dashboard and payment status. Selected axe scans are included in the browser spec; their results appear in [13](13-browser-and-unit-test-matrix-exact-commands.md). Before/after captures use 390×844 and 1440×900 Khmer, reduced motion, light appearance, with selected 390 dark management states. This is not a 320–1920 responsive matrix or WCAG certification.

**Open limits:** 320/360/430/600/768/820/1024/1920 and breakpoint-neighbor widths, 200–400% actual zoom, 844×390 and 820×430 and 768×390 on physical devices, native Khmer diacritics, VoiceOver/TalkBack, in-app browsers, onscreen keyboards, and safe-area hardware behavior are `NOT TESTED` or `BLOCKED` by absent devices. Automated axe does not determine all contrast, focus order, gesture, audio, or screen-reader behavior. No Khmer copy was changed solely for an assertion.
