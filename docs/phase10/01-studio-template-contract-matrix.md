# Studio and template contract

The accompanying JSON is generated from the actual `TEMPLATES`, component registry, capabilities and Studio source by `PHASE10_GENERATE=true` with `phase10Contract.test.jsx`. It records 36 aliases, nine dedicated renderer groups, 11 bundled catalog designs plus Event Essential, and 70 state properties. Aliases are not counted as distinct designs. The developer starter and unknown-template fallback are registry infrastructure, not catalog offerings; existing registry/security tests cover them.

Each field has a stable section/tab, state owner, serialization and permission path. Each template has a status for every field, actual renderer text probes and explicit evidence limits. Shared inheritance of the field contracts keeps the machine-readable matrix compact. All six tabs remain available, with native disclosures and legacy deep links.

Event Essential overrides the wedding control mapping with its real neutral EventDetails editor. Wedding artwork/family/closing controls are explicitly excluded there; participant controls vary by event type, and contact/access/RSVP fields outside the wedding inventory are listed separately. Preserved legacy JSON is not classified as an offered control.

Publication uses the server response; draft writes retain expectedUpdatedAt conflict protection. Supported fields use the existing content/design JSON models and media associations. Film requires the owner's current Premium entitlement. Tickets use their existing independent image purpose, owner permissions and guest QR identity.

Story remains intentionally absent from Digital Yes, Emerald, Bliss, Royal Lotus and the developer starter. Wedding party is offered only by the renderer that actually implements it (Celestial, including its aliases). Royal Lotus does not implement dress-code/FAQ sections. These exclusions hide disconnected controls, explain retained content and preserve authored values across switches. Event Essential keeps its neutral event editor rather than wedding artwork controls.

Automated scope is deliberately distinguished: all catalog templates get a representative complete browser lifecycle and actual React rendering of populated content; native HTTP/MySQL verifies shared storage, permissions, publication and Settings. This is not a claim that all 840 field/template combinations were individually edited through real HTTP and every guest device. Null/false probes can mean cover-only content, language-dependent titles or an excluded feature; they are not silently counted as passes.
