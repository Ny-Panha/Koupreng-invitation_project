# Families, name placement and monogram

`familyGroupsV1` supports two optional sides, each with a localized label and up to eight hosts. A member has a stable ID plus independent name, honorific and relationship text. Empty members are hidden; guardians and alternative hosts use the same model. Existing parent fields still render when custom groups are absent. The editor does not infer a recipient title or require both parents.

Five placement choices are available on compatible wedding renderers: template default, first partner left, second partner left, stacked and centered. CSS changes presentation without swapping the canonical groom/bride identity or DOM reading order. Long text wraps; phone widths through 430 px stack safely. A template's existing composition is retained until a host opts into custom family/layout/monogram content.

`coupleMonogram` is a versioned text/vector design: short host-controlled text, local font choice, round/oval/plain frame, none/diamond/petals motif, hex colour, size and above/below position. Decorative SVG is hidden from assistive technology; semantic partner headings remain available. No uploaded artwork or executable SVG is accepted by this maker. New vectors are original simple geometry, not copied Khmer religious or royal artwork.

Both authoring and direct API changes use the event owner's current purchased Premium snapshot. Free/BASIC callers receive 403. Collaboration permissions do not provide an independent plan grant. After expiry, unchanged private designs remain editable as part of the invitation; public output hides the design. A host can disable/remove it, but editing/reactivation requires Premium. Publishing an enabled design also requires current entitlement.

Supported and excluded renderers are enumerated in report 08 and the executed DOM matrix. Unsupported templates retain data and show an explanation instead of ineffective controls. Human Khmer typography and cultural/editorial approval remain separate from automated layout verification.
