# 14 — before/after capture and trace index

The [capture harness](evidence/capture-visual.mjs) serves isolated **pre-edit** and **post-edit** builds on loopback with Batch 12 fictional read-only fixtures. It freezes wall-clock dates at `2026-11-11T12:00:00Z` while leaving the browser performance clock native, waits for local fonts and 1.8s on renderer keys, then consumes one warm screenshot and two animation frames before retaining the evidence image. Every screenshot records route, viewport, locale, motion setting, source base SHA, page errors, unexpected fixture reads/writes, and computed styles in an ignored manifest. The post-edit manifest SHA is the base commit plus an uncommitted worktree diff until the Phase 05 commit is created; it must not be mistaken for unchanged source.

Both stages captured **52 viewport images**: public/owner/admin selected routes and 12 renderer identifiers at 390×844 and 1440×900, plus selected 390 dark management states. The final comparison has **18 changed pairs and 34 identical pairs** at the strict pixel threshold. All 11 admin images were refreshed after the final automatic-entrance CSS correction; user source stayed unchanged. They are reduced-motion, Khmer fixture captures; they do not prove normal-motion behavior or full invitation journeys. The tracked [pixel diff](evidence/capture-diff.json) is generated by [analyze-captures.py](evidence/analyze-captures.py). Raw PNGs and logs are ignored at `output/playwright/uxui-phase05-2026-11-11/before/` and `.../after/`. Playwright traces, if any, remain under app test-results and are not committed.

The actual Phase 04 before/after PNG pairs for Boilerplate, Digital Yes, Emerald, and WithJoy were visually inspected. The differences align with content animation phase and countdown movement, but source-only reasoning cannot clear parity. The first Phase 05 harness used Playwright's fixed clock, which erased performance entries. Unpainted Silk and Boilerplate content also appeared in base and post-edit diagnostic runs. The harness now freezes `Date` only and consumes an extra paint/frame before saving; this retains performance entries but **did not eliminate intermittent renderer paint differences**. Targeted repeats painted Silk in both builds, while the final full comparison still captured its desktop cover text/art absent after the edit despite matching heading/button geometry and loaded fonts. No dedicated renderer source was changed. That unexplained missing paint is an **OPEN visual gate**, not an accepted artwork change.

Both manifests contain **three page errors** from screenshot theme initialization trying to access storage in the sandboxed Studio child frame. They also contain **18 unhandled template-slug fixture reads** each, answered by the bounded fixture's 501 fallback; no network request was sent to a live provider. Both stages recorded **zero writes**. The storage errors are harness errors, and the fallback reads limit these captures to initial fallback rendering; neither is a clean full template-data verification. The current index preserves these counts instead of filtering them out. Pixel equality with reduced motion is insufficient proof of normal-motion identity.

The old `before` build is intentionally never rebuilt from a modified worktree.
