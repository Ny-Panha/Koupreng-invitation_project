# 12 — route adoption and preservation matrix

The full [135-row route adoption ledger](evidence/route-adoption.md) and [JSON](evidence/route-adoption.json) map each current leaf to app, feature group, Phase 02 primary owner and Phase 04 disposition. The script fails if a leaf lacks an owner or the 135/62 counts drift. It records 111 user and 24 admin leaves, 62 named groups, 63 app/group pairs, and 38 leaves in groups with a source-verified changed primitive. Those 38 include aliases and **do not mean 38 route workflows were browser tested**. Other leaves say `NOT VERIFIED`/`DEFERRED`, so there is no silent unassigned row.

Current actual adopters include organization create/detail, guests, delivery, QR, payment history, RSVP and assistant in the user app; dashboard, templates, reports, packages, payments, notifications, users and template edit in the admin app. Route smoke was selective: the 52-screen capture covers 11 management/public fixture groups plus renderer keys, and the new functional browser spec covers four groups. Full role/state/locale coverage is not claimed.

Preservation checks: route inventory tests passed within full user/admin suites; no route factory, backend, authorization, entitlement, price, currency, event persistence, preview protocol, editor serializer, renderer registry, or Flyway migration source was edited. There remain 48 migration SQL files. Existing ten dedicated renderer families, 38 aliases and shared/fallback identities are not modified by this diff. The before/after representative renderer comparison is in [13](13-visual-evidence-and-performance.md), with three families requiring visual review because of small capture differences. Live dynamic catalog parity is open.
