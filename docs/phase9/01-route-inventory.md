## Page-family review

| Family | Main goal and actions | Existing states / risks / verification |
| --- | --- | --- |
| Marketing/catalog/pricing/contact/venues | Discover templates and packages, open preview or checkout | MarketingShell and shared buttons; catalog loading/empty/error. Preserve artwork, localized navigation and authenticated checkout. Baseline render captures cover landing/catalog. |
| Login/register/recovery/OAuth | Establish or recover a session | AuthShell, field validation, redirects and OAuth handoff. Do not alter token expiry; Studio retains edits on 401. Provider callbacks require real credentials. |
| Events/dashboard/create/settings | Choose event, complete canonical details and save | HostShell/EventWorkspace, owned context, skeleton/error states, event-type fields and clear date semantics. Source and fixture baseline reviewed. |
| Studio/preview/publication | Edit, preview, save, review and publish | Existing serialized writes, optimistic revisions, draft recovery and PublishReview; focus/hidden editors and mobile actions are regression gates. |
| Public invitation/demo | Open cover, read program/map, RSVP/gift/ticket | Dedicated and shared renderers, invitation access checks, guest-token personalization; template themes remain independent. |
| Media/tickets/QR/delivery | Upload, personalize, export and share | Quota coupling and upload/save ambiguity require repairs; retain versioning, ownership and QR identity. |
| Guests/RSVP/seating/check-in/wishes | Maintain guest records, responses and admission | Existing paged guest APIs, event permissions, responsive states and confirmation dialogs. Do not combine guest and ticket data models. |
| Gifts/budget/reports/analytics | Record money and inspect real attendance facts | Owner/report permissions, explicit USD/KHR, server export/audit boundaries; preserve calculations and privacy. |
| Team/organizations | Invite and manage accepted collaborators | One-time recipient-bound consent, roles and owner benefit limits. Existing integration/security suite covers revocation and races. |
| Account/notifications/payments/packages | Maintain identity and understand current benefits/orders | Profile/password forms, empty/error states, real payment statuses and frozen benefit snapshots. No client price/settlement changes. |
| Admin dashboard/users/templates/packages/transactions/reports/logs/API monitor | Administer recorded platform state | Existing role gate, tables/filters/exports, honest metrics, token drift. Shared semantic styling only; preserve report scope and financial separation. |

Frontend source ownership: `src/pages`, `src/features`, `src/layouts`; route-level lazy imports are preserved. There is no separate active About page (redirects to contact). Auth/session/authorization errors are states/guards rather than independent page URLs. Dynamic account arrays include profile, password, notifications, packages, payments and organizations; event arrays include all management tools.
