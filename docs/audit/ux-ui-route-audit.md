# Koupreng UX/UI route audit

Branch: `feature/event-first-workspaces`. Scope: user frontend, preserved event ownership and payment APIs. No deployment or production operation.

## Initial audit, before implementation

The screenshot is reproducible in the existing production build with declared browser contract fixtures. Original screenshots and computed styles are in `docs/qa/ux-ui/before-*` and `before-metrics.json`. The existing frontend process on 5173 returns HTML but did not render an H1 within 30 seconds; a separate local preview on 4183 rendered the existing build. The running Java backend on 8080 returned HTTP 503 from `/actuator/health`. Neither existing process was restarted.

- **P1:** The unlayered universal reset in `src/styles/index.css` sets every element's margin and padding to zero. It overrides Tailwind's layered spacing utilities. Browser-computed history cells have **0 px padding** despite `py-3 px-4`. This is the primary cause of the collapsed table, not browser zoom (computed zoom is 1 and root font size is 16 px).
- **P1:** Packages use a 1140 px outer container, 11–14 px metadata and 1.25 heading line height. Important Khmer text is too dense. Desktop cards have approximately 287 px content width at 1440 px. History has no mobile representation or resume action.
- **P0:** Subscription `unwrap(response?.data ?? response)` turns an explicit `{data: null}` current subscription into a truthy envelope. The page then invents an active/lifetime plan. Null must stay null, and activation requires all backend activation fields.
- **P0:** Existing copy promises automatic reconciliation, 365-day validity for every plan, persistent publication after expiry and collaboration. These claims exceed verified contracts. Use actual duration/features and describe pending/review/activation accurately.
- **P2:** Six sequential event screens hide recommendations and details behind repeated Continue actions. Changing event type erases every entered field. Replace step state with a single form while retaining owner-scoped request identity and backend template validation.

Design direction: existing Noto Sans Khmer/Kantumruy stack; ivory `#fbf6ee`, white surfaces, ink `#1f2421`, muted `#59615c`, gold `#967037`, teal `#0f766e`. Left-aligned page headings, 1320 px maximum outer width, readable 16 px body/labels, 1.8 Khmer line height, restrained borders and shadows. Packages use three aligned comparison columns; creation uses a continuous form with a compact desktop summary. Primary actions remain clear at mobile widths and reserve room for support chat.

The form preserves owner-scoped UUID request identity across retries. It saves through the existing invitation API and opens only the ID returned by that API. Create Event validates the configured essential fields and a current compatible recommendation; Save Draft requires a title and validates any supplied date/time/map link. Both create a private backend draft. A localized template-section loader, stale-response guard and retry state keep the rest of the form usable. Premium access is checked through the existing access API and independently enforced when saving. A new-tab preview/purchase keeps the original tab's setup.

Shared account tokens live in `src/shared/styles/workspace-ui.css`, using approved fonts, existing brand colors, explicit surfaces/spacing, visible focus and reduced-motion overrides. Existing wedding layouts remain in place. No new form, animation or state-management dependency was added.

## Audit method and limits

Route sources: `src/app/routes/{authRoutes,hostRoutes,marketingRoutes,builderRoutes}.jsx` and the wildcard in `src/app/router.jsx`. Nested event modules require the verified event boundary. Account routes require authentication. Template checkout and host template preview have their existing guards. Public invitation access remains backend-owned.

The retained rendered inventory contains **63 concrete route instances, each inspected at 390 px Khmer and 1440 px English: 126 renders**. Screenshots and DOM measurements are retained in [the machine-readable audit](../qa/ux-ui/rendered-route-audit.json). Review covered layout, text, navigation, form semantics, loaded/empty/unavailable states, visible actions, focus and reduced motion. This is not a claim that every destructive operation, provider, arbitrary identifier or assistive technology was exercised.

Browser contract fixtures are declared in `tests/e2e/support/uxFixtures.js`; they do not replace application services. Published/guest views use declared fixtures. The independent Silk Heritage regression exercises opening, keyboard behavior, guest token and RSVP failure/retry/success. Live browser saving uses a separately started backend on 8082 with disposable H2, with no browser API-response fixtures: registration, partial draft POST, exact-ID navigation, refresh and replay of the original request. The pre-existing 8080 backend also returned real public catalog/package/recommendation HTTP 200 responses during read-only checks; its aggregate health was 503. This does not verify fresh/upgrade MySQL migration behavior.

Tables in RSVP/check-in/reports/delivery and the template category strip extend within intentional horizontal scroll regions. Their parent pages and essential form controls fit the viewport. These are recorded as P2 opportunities for richer mobile lists; clipping essential inputs was fixed separately. Some legacy module labels remain bilingual or English in Khmer mode, with small metadata and duplicated event/module headings. Those are P2 polish items, not a claim of complete localization or a full accessibility certification.
