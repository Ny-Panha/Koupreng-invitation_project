# Security, Privacy & Data Integrity Verification

## 1. Opaque Guest Invitation Tokens & Privacy

- **Token Confidentiality:** Guest links use opaque tokens (e.g. `?token=tok_sec_opaque_xyz`) rather than database primary keys or guest names.
- **Data Protection:** Accessing an invitation via token only reveals details pertinent to the guest (their name, seating table, party size). Other guests' contact information and private notes are never leaked.
- **Referrer Policy & Indexing:** Public invitation endpoints enforce `<meta name="referrer" content="no-referrer" />` and `<meta name="robots" content="noindex, nofollow" />`, preventing tokens from leaking via HTTP referrer headers when clicking external venue maps or links.

---

## 2. CSV Formula Injection Defense

- User-supplied names, phone numbers, notes, and group names are sanitized during CSV export using `safeCsvCell`.
- Prefix triggers (`=`, `+`, `-`, `@`, `\t`, `\r`) are escaped with a leading single quote (`'`), neutralizing potential remote code execution (RCE) or Dynamic Data Exchange (DDE) formulas in spreadsheet applications.

---

## 3. Idempotent Import Transactions & Web Crypto Security

- **Session Identification:** Import batches are tracked with unique UUIDs generated by cryptographically secure random values (`crypto.randomUUID()` or `crypto.getRandomValues()`).
- **Idempotency Guarantee:** Submitting the same batch ID with identical rows returns the committed receipt without duplicating guest records. Different content with the same batch ID returns a `409 Conflict`.
- **LAN HTTP Fallback:** In insecure local contexts (such as testing over LAN HTTP without HTTPS), hash generation falls back safely without disabling cryptographically secure UUID generation for the batch itself.
