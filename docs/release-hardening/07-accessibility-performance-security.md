# Accessibility, performance and security review

Runtime changes patch Java dependencies, preserve documentation through Scalar/legacy redirects, keep Safari guest-row actions focused until their click completes, and enable Enter/Space on the Emerald curtain cover. Two component cases and the bilingual browser matrix exercise the curtain fix. Frontend product layouts, Studio functionality, locale content, skeleton components and payment/authorization services are preserved. Browser test repairs target observed obsolete contracts and retain substantive assertions.

Reporting accessibility uses axe-core **4.14.0**, WCAG 2 A/AA, 2.1 AA and 2.2 AA tags. All 16 viewport/language/theme combinations passed during the matrix run. An initial serious contrast result occurred during a finite opacity entrance animation: computed ancestor opacity was below 1. Waiting for the animation's `finished` promise resolves the transient reading without changing colors, disabling animation, excluding nodes or relaxing contrast checks. Final combined scan counts appear in 08.

Keyboard flows assert drawer containment, Escape dismissal and trigger focus return. Skeleton tests assert busy-region semantics and recovery. Chromium PDF rendering and extraction validate embedded Khmer fonts; one rendered page was visually inspected. Automated emulation is not a physical-device or screen-reader test.

No event/media ownership guard, JWT expiry, HMAC verification, server-owned price, payment reconciliation or trusted settlement logic was modified. Dependency changes retain coherent Netty modules and are tested against real MySQL. Node/Python manifests and lockfiles remain unchanged. Export checks preserve private data exclusions, financial currency separation and permission denial.

The guest-row focus fix changes frontend production JavaScript; the final production build succeeds. No product layout or authored template content was changed. The broad browser suite includes viewport/zoom, reduced-motion, loading/error/retry, offline and template scenarios. Final failures and performance limitations are reported explicitly rather than inferred from unit results. No production deployment or provider payment was attempted.

Production bundle comparison (Node 22): entry JavaScript **432.73 kB** both before and after; gzip **129.35 ? 129.30 kB**. Emerald's split chunk **18.51 ? 18.61 kB**, gzip **5.58 ? 5.64 kB**. These build measurements show no major bundle growth; they are not a production latency measurement.

The existing RSVP summary MySQL benchmark passed against 0/100/1,000/10,000/100,000 records, three rounds, ten warmups and thirty measured calls per round. It exercises the existing seven-query versus four-query implementations; no query optimization is claimed as a change in this task. At 100,000 records the first measured p95 was 1,177.83 versus 595.92 ms. Runs shared a development machine with other checks, so they are diagnostic comparisons, not an SLA. Production traffic/load testing and dedicated Studio/ticket/media heap-leak profiling were not performed. Existing navigation, offline retry, acknowledgement, frame identity and skeleton stability assertions are exercised by the browser suites.
