# Phase 2 product policy decisions

Phase 2 now supplies a central `EntitlementService`. Free templates and independently purchased access remain available; an ACTIVE, PAID, unexpired subscription can grant its explicit premium-template benefit. Pending, inactive, future-start and expired orders do not grant that benefit. Hiding a package from the sales catalog does not silently revoke an already-paid subscription.

`ENFORCE_PACKAGE_POLICY=false` preserves existing free capabilities. Opt-in enforcement requires an owner-reviewed zero-price package code, instead of inventing a new free-tier limit. Invitation creation and owner guest creation/import limits check under the owner row lock. QR/seating/check-in feature controls use the same policy; null limits mean unlimited, zero means no additions, and negative limits fail with a configuration-review error. No strict policy has been enabled or seeded automatically.

Team-member scope (per organization versus per account), branding scope, advanced-report scope, AI entitlement scope and the approved free package remain **PRODUCT_POLICY_REVIEW_REQUIRED**. Team, branding, advanced-report and AI routes do not yet enforce their commercial flags. Public RSVP creation shares the same transactional guest-quota boundary as owner guest creation when strict policy is enabled. The central policy boundary is ready for the remaining decisions; existing capability URLs, recovery, exports and historical data remain usable. Selecting or enabling a commercial baseline is not part of this remediation.

The public template contract now exposes `checkoutEligible`, `checkoutAmount`, `checkoutCurrency` and `checkoutPolicy` independently of the editable display price. The existing Garden static offer remains server-owned USD 0.01. Other active premium entries explicitly require a reviewed offer/provider mapping; no automatic bank-link assignment or use of an arbitrary edited catalog price occurs. Free preview/design selection is preserved. The mismatch between the free Garden catalog entry and its optional legacy checkout remains a product decision.

Contact delivery requires a configured SMTP transport and `CONTACT_RECIPIENT`. Success means **SMTP_ACCEPTED**, not confirmed inbox delivery. No real messages are sent by the remediation tests. AI source values distinguish **AI_PROVIDER** from **LOCAL_TEMPLATE**; five internal operations and safe timeout/failure behavior are tested using adapters only. No real provider selection, key setup or paid AI calls occur.

These decisions do not block independent remediation. Existing features, data and integrations stay preserved while unresolved commercial choices remain explicit.

| Area | Current evidence | Conservative implementation / required decision |
|---|---|---|
| STAFF privileges | Java authentication currently maps STAFF to ROLE_ADMIN. | Preserve that mapping and add a forward-only MySQL enum expansion. A narrower staff role requires a separate approved permission matrix. |
| Subscription capabilities | Packages contain feature flags and quota values; current mutations do not consistently enforce them. | Centralize entitlement evaluation and existing template-access enforcement. Preserve existing free capabilities until the free-versus-paid feature matrix is confirmed. `PRODUCT_POLICY_REVIEW_REQUIRED` applies to activation of additional quota/feature restrictions. |
| Template checkout | Existing static checkout authorizes only the active Garden code and USD 0.01. V16/V22 catalog seeds describe free templates; admin can set other prices. Existing production validator restricts bank links. | Keep authorized static bank links and server-owned amounts. Do not infer a working checkout for every active premium template or treat a client amount as authority. Confirm the intended paid catalog, offer-to-bank-link mapping and supported provider mode before broadening checkout. `NEEDS_PRODUCT_DECISION`. |
| AI provider | No supported provider implementation or selected credentials/cost policy exists. | Implement authenticated internal adapter contracts and mock tests, retaining explicit local-template fallback. Provider/model, credentials, usage limits and cost policy need a product decision. No credential provisioning or real AI calls occur in this phase. |
| Historical template references | V16 overwrote invitation, order and access template references without an authoritative mapping. | `NEEDS_OWNER_DECISION`; follow PHASE2_TEMPLATE_RECOVERY.md with pre-V16 evidence. No guessed backfill or historical migration rewrite. |
| Budget cap currency | Legacy budget caps have a numeric amount without a stored currency. Items support USD and KHR. | Separate item totals by currency and stop presenting mixed totals as a single comparable amount. Keep existing caps unchanged. Confirm cap currency and historical interpretation before a currency backfill or currency-specific cap migration. No invented FX conversion. |
| Public RSVP aggregate | Existing backend aggregate API can serve a public invitation; an additional UI is optional. | Preserve privacy/access rules and capability. Add UI only for an identified guest need; do not expose guest contacts, tokens or private host reports. |
| Legacy event/customization/audit APIs | Legacy ADMIN events remain distinct; main editor already persists customization; admin system/recent logs already provide useful audit UI. | Preserve all APIs/models. Keep current equivalent UI where it meets the product need; do not add redundant editors or erase legacy models. |

Policy decisions must not weaken owner checks, purchased-access checks, trusted payment confirmation, CSRF, token revocation or production security validation.
