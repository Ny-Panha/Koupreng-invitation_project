# Themes, dark mode and cascade

Customer `ThemeProvider` writes `document.documentElement.dataset.colorMode` from `koupreng.colorMode`; admin `AdminLayout` uses root `.dark` from `localStorage.theme` and system preference before paint. Neither store, toggle behavior nor account persistence schema changed. Canonical source defines light roles on `:root`, dark management roles on `:root.dark, :root[data-color-mode="dark"]`. The dark block occurs after light. Only admin's `.dark` legacy warning bridge remains in `styles/index.css`.

User `--app-*` aliases now resolve the `--ui-theme-*` values. `.dash-wrapper` intentionally maps old `--ui-*` and `--ws-*` names to those application roles, so existing owner components follow appearance. Marketing `--kp-public-*` and auth scoped CSS map core surfaces, fields, text and actions. Admin Tailwind aliases (`--background`, `--foreground`, `--card`, `--primary`, `--border`, `--input`, `--ring`, etc.) resolve the same roles. Template Studio uses `--ui-studio-*` dark chrome in both admin appearance modes; the preview iframe remains independent.

Example: `var(--primary)` resolves through `--ui-theme-action`, so light is `#2e433a` and dark is `#b7d2b8`; `--primary-foreground` pairs with white and `#19271e` respectively. User `--app-canvas` changed from `#f6f7f3/#111a16` to `#fbf6ee/#172019`. Admin dark `--background` changed from `#09090b` to `#172019`. Auth dark before had light heading text; after it computes `rgb(240,243,238)` on dark card `rgb(32,42,36)`.

**Cascade rule:** do not place blanket `.dark *` color declarations or retheme `[data-template-renderer]`, `[data-theme=wed]`, invitation root CSS, preview iframe or template media. Existing invitation palettes and display fonts are authored per renderer. Keep high-specificity `:root .dash-wrapper` overrides within owner chrome. When updating a component, use a semantic role at the component root and inspect both modes in the browser; unresolved hard-coded child selectors may still win. Reduced motion zeros `--ui-duration-feedback/overlay`; existing app/Studio reduced-motion rules remain.

The sync script's `--check` and unit test prove source/mirror identity. They do not prove every visual child selector is migrated. The remaining role adoption is assigned in [07](07-real-surface-adoption-matrix.md) and [13](13-phase04-component-adoption-plan.md).
